# Frontend

The "frontend" for a knowledge project is the `wiki/` directory - the knowledge
base generated and maintained by the 'wiki' skill.

→ kp-wiki skill spec: [product-specs/wiki.md](product-specs/wiki.md)

---

## Two entry points, two audiences

The KB exposes two entry points by design. Both are generated by the 'wiki' skill
and rebuilt on every `kp-wiki build` run.

### `wiki/index.yaml` - agent entry point

Structured YAML. Agents read this first; it requires no Markdown parsing and
provides a typed, navigable map of the entire knowledge base.

```yaml
# wiki/index.yaml - generated, do not edit by hand
version: "1"
last_built: "2026-06-21T14:00:00Z"
source_count: 12
entity_count: 84

glossary: glossary.md

pages:
  concepts:
    - title: "Large Language Model"
      file: concepts/large-language-model.md
      aliases: ["LLM", "language model"]
      sources: [src-001, src-004]
  people:
    - title: "Jane Smith"
      file: people/jane-smith.md
      sources: [src-002]
  organizations: []
  events: []

search_hints:
  primary_topics: ["machine learning", "inference", "fine-tuning"]
  key_entities: ["Large Language Model", "Jane Smith"]
```

`index.yaml` is the **agent contract** for the KB. Its schema is versioned.
See [ARCHITECTURE.md](../ARCHITECTURE.md) for the versioning rule.

---

### `wiki/index.md` - human / Obsidian entry point

A Markdown page designed as the starting node for Obsidian's graph view or the
Foam extension in VS Code. Lists all pages grouped by entity type, links to
`glossary.md`, and provides a short description of the KB's scope and source count.

This file is always regenerated. Manually edited content will be lost on the
next `kp-wiki build` unless the page frontmatter carries `manual: true`.

---

## `wiki/glossary.md`

The resolved glossary rendered as a single Markdown file. Agents can load it
directly as context; humans can read it in any Markdown editor.

Format: alphabetically sorted entries, each with:
- canonical term
- aliases (if any)
- short definition
- source references (links to the originating extraction)
- related terms (wikilinks)

---

## Target editors

`wiki/` Markdown files are designed to render correctly in:

- **Obsidian** - primary target. `[[wikilinks]]` are native, graph view works,
  `glossary.md` integrates with the Obsidian dictionary plugin.
- **VS Code + Foam** - secondary target. Foam resolves `[[wikilinks]]` and
  provides a graph view panel.
- **Any Markdown renderer** - fallback. Wikilinks degrade to visible text;
  content remains readable.

## File and directory conventions

### Naming
`wiki/` files use `kebab-case.md`. Spaces in topic names become hyphens.
A topic named "Large Language Model" produces `wiki/concepts/large-language-model.md`.

Pages are grouped in subdirectories by entity type:

```
wiki/
├── index.yaml
├── index.md
├── glossary.md
├── queries/          # compound query knowledge - see below
│   └── YYYY-MM-DD-<slug>.md
├── concepts/
├── people/
├── organizations/
├── events/
└── topics/             # cross-cutting themes that don't fit a single entity type
```

### Question files (`wiki/queries/`)

One Markdown file per question, named by date and a short slug.
Read by Obsidian like any other KB page; read by `/kp-wiki build` as a feedback input.

```markdown
---
date: 2026-06-21
question: "What are the main findings in the 2025 report?"
confidence: high          # high | medium | low
answer_sources:
  - type: wiki_page
    ref: wiki/concepts/findings-2025.md
  - type: extraction
    ref: staging/src-001.json
  - type: source
    ref: sources/src-001/report-2025.pdf
related_questions:
  - 2026-06-20-what-changed-since-2024.md
---

## Question
What are the main findings in the 2025 report?

## Answer
...

## How this was answered
The answer was composed from the KB page [[findings-2025]] (high confidence)
and cross-checked against the raw extraction for `src-001`.
```

`confidence` and `answer_sources` are the fields that `/kp-wiki build` acts on.
`related_questions` is populated by `/kp-query --related` for navigability in Obsidian.

### Frontmatter
Every KB page carries YAML frontmatter:

```yaml
---
title: <topic name>
entity_type: concept | person | organization | event | topic
generated: true        # false if the page was manually pinned
sources:
  - <source-id>
last_built: <ISO date>
---
```

Pages with `generated: false` are not overwritten by `kp-wiki build`.

### Wikilinks
Internal links use `[[page-name]]` syntax. The 'wiki' skill resolves all
entity and glossary term references to their canonical page name before writing.
Broken links are reported as warnings, not errors.

---

## What `wiki/` does not contain

- Raw source files - those live in `sources/`
- Extraction JSON - that lives in `staging/`
- The machine-readable glossary used during synthesis - that is an intermediate
  artifact; `wiki/glossary.md` is the rendered output for agents and humans
